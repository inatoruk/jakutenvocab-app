# AI応答速度の検証（2026-10-29）

モデルは `gemini-3.5-flash-lite` のまま。新しい有料サービスや定期的なAI呼び出しは追加していない。

## 変更

- Vercel Functionsの実行地域を `iad1` から `hnd1` に変更。
- 意味・例文をNDJSONで逐次表示。JSON APIとの互換性は維持。
- タブ内メモリに意味・文脈付き言い換え判定を30分、合計最大200件保持。例文は使い回さない。
- グループ提案で独立した2つのDB問い合わせを並列実行。
- 入力本文やAPIキーを含めずに `ai-timing` を記録。JSON応答では `Server-Timing` も提供。

## 限界と次の調査

- 初回の実生成を一律10倍速にしたわけではない。キャッシュが有効な繰り返しでは外部通信を省略できる。
- 最大10秒は今回再現できていない。時間帯、放置時間、ブラウザ側の計測との突き合わせが必要。
- グループ提案は本人の認証付きデータが必要なため実測していない。
- ストリーミングは全文完了前の表示を可能にするが、最初の文字以前の待ち時間は消せない。
- 定期pingや自動先読みで無料枠を消費する処理は追加していない。

## 新規生成0.2秒を目標にした追加検証

登録済みデータやタブ内キャッシュの命中は評価に含めていない。対象は生成リクエスト開始から実際の最初の文字まで。

- 既存プロンプト、短縮プロンプト＋明示的なminimal thinking、REST直接通信を8回比較。最初の文字まで約0.55–1.37秒で、短縮やSDKの省略による明確な優位は確認できなかった。品質条件を削る短縮プロンプトは採用していない。
- 入力開始時にサーバーとGoogleへのHTTPS接続だけを準備する試作を本番で検証。新規単語6件の最初の文字まで1.123–4.240秒。サーバー内準備は0–4ms、AI呼び出し内の初回文字待ちは約0.842–4.187秒。期待した改善を確認できなかったため、試作コードと公開デプロイは取り消した。
- 公開URLを変更せず、同じコードを米国西海岸 `sfo1` に配置して比較。

| 生成対象 | 東京 hnd1 | 西海岸 sfo1 |
| --- | ---: | ---: |
| sustain の意味 | 2.069秒 | 1.203秒 |
| evaluate の例文 | 1.089秒 | 0.690秒 |
| reimburse の意味 | 1.145秒 | 2.372秒 |

西海岸は保護されたデプロイにVercel CLIでアクセスし、curlのtime_starttransferを計測（CLIの認証処理時間は除外）。東京はfetchで最初のdeltaを計測。厳密な同時条件ではなく、各3回なので一般的な性能差や最大待ち時間を断定しない。どちらも0.2秒未達、西海岸が一貫して速い結果ではないため、本番は東京を維持した。

モデルとAPIキーは変更していない。定期pingや未承諾の先読み生成も追加していない。今回の結果だけでは、無料の外部APIによる新規生成を0.2秒で開始できるとは言えない。入力中の先読みはクリック後の待ちを減らす別案だが、使われない生成にも無料枠を消費するため未実装。


### ユーザーの方針確定

先読み生成は不採用、接続準備のみを有効化する指示を受け、入力欄のフォーカス・入力・生成ボタンへのフォーカス／ポインター移動でHEADリクエストを送る実装を追加。連続操作は10秒に1回に制限し、定期送信はしない。HEADはGoogleへプロンプトもAPIキーも送らず、HTTPS接続のみ準備する。失敗しても生成は妨げない。前述の通り、速度改善や0.2秒達成を保証するものではない。


## 継続改善: 接続・API・極小生成の切り分け

- HTTP/2の接続確立は51ms。同じ接続を再利用しても最初の文字まで684–2,812ms（4回）。SDK側は770–2,695ms（4回）で、一貫した短縮なし。
- 保存なしInteractions APIは619–792ms（2回）、GenerateContentは513–1,324ms（2回）。両方式とも内部思考トークン0で、0.2秒未達。サーバー生成メタデータは最初の文字に数えていない。
- 診断用の固定1語出力でも635–1,637ms（3回）。語彙の意味を生成しない診断なので、目標達成の実績には使わない。同時に試した意味生成は628–1,008ms（3回）、思考トークン0。
- Google公式gRPCストリーミングの比較では604・610ms、同じ単語・既定設定のRESTでは704・707ms（各2回）。小標本では約0.1秒の差が出たが、品質・失敗時処理・本番での再現性を確認する前に公開方式を変更しない。
- 直近の既存本番は1,541・2,649ms（新規単語2件、キャッシュなし）。計測スクリプトは描画完了を測らないため、最初の実テキスト到着の指標である。

再現用計測器: `node scripts/benchmark-ai-latency.cjs --mode production --samples 3`。直接通信の比較には `--mode generate` または `--mode interactions` を指定する。APIキー・生成本文は出力せず、失敗・途中終了・メタデータ・思考文を速い成功として数えない。HTTP 429等では自動再試行せず停止する。生の集計値は `docs/benchmarks/` に保存。

目標は未達。無料枠、現行Flash-Lite、先読み生成なしの条件と、破壊的変更前に確認を取る方針を維持して継続する。
